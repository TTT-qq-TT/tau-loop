# TauLoop：第一次使用

[English](first-use.en.md) | **简体中文**

> 你不需要先学会一套工作流，才有资格把项目交给 agent。
>
> 只要说清你想做到哪里。TauLoop 会让项目留下正在做什么、已经验证了什么，以及接下来该做什么。

## 从一句话开始

在项目里直接对 agent 说：

```text
用 TauLoop 把当前项目推进到 xxx。

能自己验证的就继续；真正需要我决定时再停下来。
```

把 `xxx` 换成你真正想达到的结果，例如：完成一个功能、修复一类问题、把环境配置好，或推进到可以 review 的状态。

第一次使用还没有安装 TauLoop 时，把仓库链接一起发给 agent：

```text
请阅读并安装 https://github.com/TTT-qq-TT/tau-loop ，然后用 TauLoop 把当前项目推进到 xxx。

能自己验证的就继续；真正需要我决定时再停下来。
```

你不必先记住命令，也不必先理解 `spec`、`checkpoint` 分别是什么。

## 你只需要选一种节奏

### 先看一眼路线

不想立刻开始时，说：

```text
先给我看计划和每一段的完成标准；我确认前不要实现。
```

你会先看到项目准备怎样推进、每段怎样才算完成，以及哪些地方需要你的选择。

### 持续往前走

目标和边界已经清楚时，说：

```text
按计划继续推进。每完成一段就验证、留下 checkpoint，再开始下一个未阻塞的部分。
```

你不需要替 agent 逐步接力。它应当在能用证据确认的范围内自己完成下一段。

### 让长任务安静地跑

下载、安装、构建或测试需要等待时，说：

```text
用 TauLoop 完成 xxx。
把下载、安装和检查排成有验证的步骤；前一步没有通过就不要开始下一步；不要频繁查看下载进度。
```

启动后，agent 会把长任务交给操作系统托管的进程，配一个系统定时器（值班模式）：定时器会周期性地拉起一个短暂的巡检回合（headless agent），它看看日志尾部、查查进程、比对预期产物，安全修复，更新状态后退出。真正的等待者是本地进程，不是聊天窗口；「进程还活着」不等于「任务完成」，完成必须来自实际通过验证的证据。

## 你会反复听到这几个词

- **spec**：一段工作的契约。agent 会把目标拆成若干段，每段先写清「改哪里、怎样算完成、怎么验证」再动手；范围变了就先改 spec。
- **plan**：项目的路线图——当前目标、走到哪一步、下一步是什么。想看进展，直接说「给我看当前 plan」。
- **checkpoint**：一段工作结束时的现场——刚做了什么、证据在哪、下一步是什么。换窗口或隔天回来，agent 从这里继续。
- **memory**：项目还值得记住的事实——不是聊天全文，是结论、已验证的环境事实和已知风险。
- **长任务约定**：下载、构建这类慢活由操作系统托管进程，agent 定期醒来检查（前面已讲），不占聊天窗口。
- **handoff（换窗交接）**：窗口快满或想把讨论与执行分开时，说「请 handoff 给下一个窗口」。agent 会写好交接文件，给你一句启动语；新窗口粘贴即可无缝继续，不用重新解释。

## 之后，项目会记得

一段工作结束后，项目里会留下计划、完成标准、验证结果和下一步。下次换一个上下文、隔天再打开项目，agent 从这些事实继续，而不是让你重新解释上一段聊天。

你随时可以问：

```text
给我看当前计划、最后一个已验证的结果，以及可以安全继续的下一步。
```

## TauLoop 会在这些时候停下

它不是为了让 agent 什么都自己决定。下面这些事仍然应该由你确认：

- 新权限、费用、凭据或不可逆操作；
- 验证失败后需要改变策略；
- 产品取舍、发布，或任何你明确要求 review 的节点；
- 无法确认一个中断任务是否还能安全继续时。

进程还在运行或日志还在输出，都不算完成。完成必须有实际的验证证据。

## 想多了解一点？

你不需要现在读完。需要查看工作如何记录、长任务如何恢复、受限修复如何运行、或想手动使用命令时，再读[完整使用手册](user-manual.md)。

下一次只要告诉 agent：你想把项目推进到哪里，以及「能自己验证的就继续；真正需要我决定时再停下来」。
